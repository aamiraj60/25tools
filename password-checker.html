      Why it matters

      Why entropy beats a complexity checklist

      Entropy is measured in bits, and each bit doubles the size of the search space. A password drawn from a 62-character alphabet — letters and digits, mixed case — gains about 5.95 bits for every character. Twenty such characters carry roughly 119 bits, which is why the length of a password dominates every other property. Adding a symbol widens the alphabet from 62 to 95, a gain of well under one bit per character; adding a single character to a 20-character password gains nearly six. Length wins, almost every time.

      The catch is that raw entropy assumes the characters are chosen uniformly at random, and human beings never do that. People reach for names, dates, keyboard runs and the same handful of passwords that breach lists are built from. Password123! satisfies a nine-character policy with every character class and still carries under thirty bits of genuine entropy, because an attacker's dictionary tries it in the first few thousand guesses. A naive calculator reports it as strong; this one subtracts a pattern penalty for the repetition, the sequence, the year and the predictable word, and the score drops accordingly.

      That is the difference between a password meter that flatters you and one that protects you. The goal is not to reach a particular colour on a bar; it is to understand, in plain numbers, how much work an attacker has to do and where that work collapses. Once you can see the bits, the advice writes itself: make it longer, make it random, and never reuse it.

      Security notes

      Password habits that age well

      Length first, always. Every extra character multiplies the search space, while extra character classes barely widen it. A passphrase of four or five unrelated words, or a random string of twenty or more characters, will outlast almost any eight-character jumble — and the tool's own entropy readout proves it in a single glance.

      Unique, always. The damage of a breach is not that one password leaked; it is that the same password works somewhere else. A password manager removes the trade-off between “long and random” and “something I can remember”, which is why the recommendation is not a preference but a fix for the root cause. Generate here, store there, never reuse.

      Remember what the estimate does and does not cover. Time-to-crack figures assume the attacker is working against a fast hash such as MD5 or SHA-1; a slow, salted password hash like bcrypt, scrypt or Argon2 raises the cost by orders of magnitude and buys you real time. The estimate also assumes a well-implemented generator or a truly random choice — if the password is a phrase a human invented, the real entropy is lower than the alphabet maths suggests, which is exactly why the pattern penalty exists.

      Finally, treat two-factor authentication as the safety net rather than the plan. A strong, unique password stops the credential-stuffing attack; a second factor stops the attacker who already has the password. Use both, and check the password you are relying on right here before you trust it.

      Questions

      Frequently asked questions

      Is it safe to type my real password into this checker?

      Yes. The analysis runs entirely in your browser with JavaScript — there is no server call at all. If you want proof, open your browser's developer tools, switch to the Network tab, and watch it stay empty while you type. You can even disconnect from the internet and the tool keeps working.

      What is entropy and what is a good number of bits?

      Entropy measures how many guesses a password resists, expressed in bits. Each additional bit doubles the work for an attacker. Below 40 bits falls quickly to an offline attack, 60 bits is reasonable, 80 bits is comfortably strong, and 100 bits or more is beyond any practical attack with today's hardware.

      How is the time-to-crack estimate calculated?

      The tool takes the entropy in bits, halves it to model the average case, and divides by the guess rate of each hardware scenario — from a rate-limited online attack up to a nation-state cracking farm. Every figure is a best-case estimate for the attacker against a fast hash, so treat it as a floor rather than a guarantee.

      Does a longer password always beat a more complicated one?

      Almost always, yes. Adding characters multiplies the search space, while adding a symbol only widens the alphabet slightly. A 20-character passphrase of ordinary words is far stronger than an 8-character jumble, which is why length is the single most effective lever you have.

      Should I use a password manager?

      Yes. A manager lets every account have a long, unique, random password that you never have to remember, which removes the two biggest real-world risks: reusing a password and choosing a short one. Generate the password here, save it there, and never reuse it across sites.

      Does this tool check whether my password has been breached?

      No, and deliberately so. A breach check would have to send a hash of your password to a third-party service, which breaks the privacy guarantee. Instead, the tool flags the patterns that breach lists are built from — common passwords, keyboard runs, years and predictable words — without your password ever leaving the device.

      Are the generated passwords truly random?

      Yes. The generator draws from the browser's Web Crypto API, the same cryptographically secure random source used for TLS keys, rather than Math.random. It also guarantees at least one character from every selected class and shuffles the result with fresh entropy, so the order is not predictable.
